1. INTRODUCTION                                               *aws-nvim-intro*

aws.nvim lets you interact with AWS without leaving Neovim. AWS CLI output is
placed into regular Neovim buffers inside splits, so all built-in motions,
search, and keymaps work out of the box.

All CLI calls are asynchronous (|vim.loop| / libuv); the editor never blocks
while waiting for AWS responses. Remote resource deletion and S3 bucket emptying
are disabled in aws.nvim.

Supported services:
  - AWS CloudFormation
  - AWS S3
  - AWS CloudWatch
  - AWS Lambda
  - AWS ACM (Certificate Manager)
  - AWS Secrets Manager
  - AWS CloudFront
  - AWS API Gateway
  - AWS ECS / Fargate
  - AWS IAM
  - AWS VPC
  - AWS DynamoDB
  - AWS EC2

==============================================================================
2. REQUIREMENTS                                        *aws-nvim-requirements*

  - Neovim >= 0.9
  - AWS CLI v2 (recommended)

Authentication is entirely delegated to the user. The plugin assumes the `aws`
binary is on $PATH and that credentials are already configured (environment
variables, ~/.aws/credentials, SSO, IAM role, etc.).

If a CLI call fails the raw stderr output is shown verbatim in the buffer.

3. INSTALLATION                                        *aws-nvim-installation*

lazy.nvim ~
>lua
    {
      "jugarpeupv/aws.nvim",
      config = function()
        require("aws").setup()
      end,
    }
<

packer.nvim ~
>lua
    use {
      "jugarpeupv/aws.nvim",
      config = function()
        require("aws").setup()
      end,
    }
<

After installation, run the following to generate the help tags: >

    :helptags ALL
<

4. CONFIGURATION                                      *aws-nvim-configuration*

All options are optional. Call `setup()` with any overrides: >lua

    require("aws").setup({
      -- Default AWS CLI environment overrides applied to every command.
      -- Authentication must already be handled by your environment.
      default_aws_profile = nil,  -- sets AWS_PROFILE for every CLI call
      default_aws_region  = nil,  -- sets AWS_DEFAULT_REGION for every CLI call

      -- Status icons shown in the CloudFormation stacks buffer.
      -- Requires a Nerd Font; replace with ASCII strings if needed.
      icons = {
        stack       = "󰆼 ",
        complete    = "󰱑 ",
        failed      = "󰱞 ",
        in_progress = "󰔟 ",
        deleted     = "󰩺 ",
      },

      -- Buffer-local keymaps for each service.
      -- Set any key to false to disable it entirely.
      keymaps = {
        cloudformation = {
          open_resources = "<CR>",  -- open resources for stack under cursor
          open_events    = "E",     -- open events for stack under cursor
          filter         = "F",     -- prompt to filter stacks by name
          clear_filter   = "C",     -- clear active filter
          refresh        = "R",     -- re-fetch stacks from AWS
        },
        s3 = {
          open_bucket  = "<CR>",  -- open bucket under cursor in oil.nvim
          filter       = "F",     -- prompt to filter buckets by name
          clear_filter = "C",     -- clear active filter
          refresh      = "R",     -- re-fetch buckets from AWS
        },
        cloudwatch = {
          open_streams = "<CR>",  -- open log streams for group under cursor
          open_logs    = "<CR>",  -- open log events for stream under cursor
          filter       = "F",     -- prompt to filter log groups by name
          clear_filter = "C",     -- clear active filter
          refresh      = "R",     -- re-fetch from AWS
        },
        lambda = {
          open_detail  = "<CR>",  -- open detail view for function under cursor
          open_logs    = "L",     -- open CloudWatch log streams for function
          filter       = "F",     -- prompt to filter functions by name
          clear_filter = "C",     -- clear active filter
          refresh      = "R",     -- re-fetch from AWS
          detail_logs  = "L",     -- open CW log streams from detail buffer
        },
        acm = {
          open_detail    = "<CR>",  -- open detail view for certificate under cursor
          filter         = "F",     -- prompt to filter certificates by domain
          clear_filter   = "C",     -- clear active filter
          refresh        = "R",     -- re-fetch from AWS
          detail_refresh = "R",     -- refresh the detail view
        },
        secretsmanager = {
          open_detail    = "<CR>",  -- open detail view for secret under cursor
          filter         = "F",     -- prompt to filter secrets by name
          clear_filter   = "C",     -- clear active filter
          refresh        = "R",     -- re-fetch from AWS
          detail_refresh = "R",     -- refresh the detail view
          reveal         = "gS",    -- toggle reveal / hide secret value
        },
        cloudfront = {
          open_detail       = "<CR>",  -- open detail view for distribution
          invalidate        = "I",     -- create a cache invalidation
          filter            = "F",     -- prompt to filter distributions
          clear_filter      = "C",     -- clear active filter
          refresh           = "R",     -- re-fetch from AWS
          detail_refresh    = "R",     -- refresh the detail view
          detail_invalidate = "I",     -- invalidate from the detail buffer
        },
        apigateway = {
          open_detail    = "<CR>",  -- open detail view for REST API under cursor
          filter         = "F",     -- prompt to filter APIs by name
          clear_filter   = "C",     -- clear active filter
          refresh        = "R",     -- re-fetch from AWS
          detail_refresh = "R",     -- refresh the detail view
        },
        ecs = {
          open_detail    = "<CR>",  -- open cluster detail (services + tasks)
          filter         = "F",     -- prompt to filter clusters by name
          clear_filter   = "C",     -- clear active filter
          refresh        = "R",     -- re-fetch from AWS
          detail_refresh = "R",     -- refresh the detail view
        },
        iam = {
          open_list      = "<CR>",  -- open resource list from the menu
          open_detail    = "<CR>",  -- open detail view for resource under cursor
          filter         = "F",     -- prompt to filter resources by name
          clear_filter   = "C",     -- clear active filter
          toggle_scope   = "T",     -- toggle policy scope Local <-> All
          refresh        = "R",     -- re-fetch from AWS
          detail_refresh = "R",     -- refresh the detail view
        },
        vpc = {
          open_detail    = "<CR>",  -- open VPC menu (list) or section (menu)
          filter         = "F",     -- prompt to filter VPCs by name or ID
          clear_filter   = "C",     -- clear active filter
          refresh        = "R",     -- re-fetch from AWS
          detail_refresh = "R",     -- refresh a menu, section, or detail buffer
        },
        dynamodb = {
          open_menu      = "<CR>",  -- open per-table menu from the list buffer
          filter         = "F",     -- prompt to filter tables by name
          clear_filter   = "C",     -- clear active filter
          refresh        = "R",     -- re-fetch from AWS (list buffer)
          menu_open      = "<CR>",  -- open section from the per-table menu
          menu_refresh   = "R",     -- refresh the per-table menu
          detail_refresh = "R",     -- refresh a detail or scan buffer
          scan_run       = "R",     -- run / re-run the scan or query

------------------------------------------------------------------------------
                                                   *aws-nvim-default-profile*
`default_aws_profile`
    Sets the `AWS_PROFILE` environment variable for every CLI call made by the
    plugin. Equivalent to passing `--profile` to every command.
    Default: `nil` (uses the environment as-is).

                                                    *aws-nvim-default-region*
`default_aws_region`
    Sets the `AWS_DEFAULT_REGION` environment variable for every CLI call.
    Equivalent to passing `--region` to every command.
    Default: `nil` (uses the environment as-is).

                                                          *aws-nvim-keymaps*
`keymaps`
    Table of buffer-local keymaps organised by service. Each value is a key
    string accepted by |vim.keymap.set()|, or `false` to disable the binding
    entirely.

5. PER-COMMAND FLAGS                                         *aws-nvim-flags*

Every `:Aws*` command accepts optional `--region` and `--profile` flags that
override |aws-nvim-default-region| / |aws-nvim-default-profile| for that
single invocation. The flags can appear anywhere in the argument list. >

    :AwsCF list --region us-east-1
    :AwsCF list --profile prod --region eu-west-1
    :AwsS3 --region ap-southeast-1
    :AwsCW list --profile staging
<

Tab-completion is available for both flags and sub-commands.

`:AwsCW list` also accepts `--fresh` to bypass the in-memory cache and force
a fresh fetch from AWS.

6. SERVICE PICKER                                *aws-picker* *aws-nvim-picker*

`:AwsPicker` opens a fuzzy finder listing all supported services. Selecting
an entry opens that service's list buffer immediately.

The picker automatically uses the best available backend:

  Priority  Backend              Requirement ~
  1         snacks.nvim          `folke/snacks.nvim` loaded
  2         Telescope            `nvim-telescope/telescope.nvim` loaded
  3         `vim.ui.select`      always available

                                                                *:AwsPicker*
:AwsPicker [--region {r}] [--profile {p}]
    Open the service picker. The selected service opens with the supplied
    --region / --profile overrides applied.

AWS profiles                                        *aws-nvim-profile*

    Profiles are read from ~/.aws/config or $AWS_CONFIG_FILE. Only `[default]`
    and `[profile <name>]` sections are profiles; `[sso-session ...]`,
    `[services ...]` and other sections are ignored. Duplicate profile
    sections merge with last-wins, and a missing region is allowed.

        [profile dev]
        role_arn = arn:aws:iam::123456789012:role/PowerUser
        source_profile = default
        region = ap-northeast-1

    The current profile resolves as $AWS_PROFILE, then the profile selected in
    this session, then `default`. Selecting a profile runs
    `vim.env.AWS_PROFILE = <name>` and emits `User AwsProfileChanged`, which
    redraws the statusline.

    Lua API:

        require("aws.profile").current()      -- "dev"
        require("aws.profile").set("prod")    -- returns "prod"
        require("aws.profile").profiles()     -- { "default", "dev", ... }
        require("aws.profile").region("dev")  -- "ap-northeast-1" or nil
        require("aws.profile").summary()      -- "dev@ap-northeast-1"
        require("aws.profile").reload()

    Heirline:

        local AwsProfile = require("aws.profile").component()

    The component hides itself when no profiles exist and opens the picker on
    left click.

------------------------------------------------------------------------------
Resource actions                                  *aws-nvim-resource*

    Every action discovers the resource from the current buffer:

    1. `.aws-resource.json`, searched from the current file upwards:
           {"type":"lambda","account":"123456789012",
            "region":"ap-northeast-1","profile":"sbi-dwh-dev",
            "function_name":"dwh-dev","log_group":"/aws/lambda/dwh-dev"}
    2. legacy `.aws-meta.json` written by the Lambda download;
    3. directory layout `lambda/<name>`, `stepfunctions/<name>`,
       `glue/<name>`;
    4. the AWS Explorer Lambda buffer under the cursor.

    When nothing identifies a resource the action stops with
    "❌ AWS resource metadata not found".

    Upload saves modified buffers with `:wall`, builds `function.zip`
    inside the resource directory (excluding .git, .github, __pycache__,
    .pytest_cache, .venv, node_modules, *.pyc, function.zip and
    .aws-resource.json), prints function, profile, region and account, then
    runs:

        aws lambda update-function-code --function-name {name} \
          --zip-file fileb://function.zip [--profile {p}] [--region {r}]

    Success shows "Upload Success" with function, region, account and
    profile. Failure shows the raw AWS CLI error. Invoke, logs and refresh
    read the same metadata. `stepfunctions` and `glue` layouts are detected
    but their actions are not implemented yet.

Functions buffer                                      *aws-nvim-lambda-keys*
    filetype: `aws-lambda`

    Key   Action ~
    <CR>  Open the detail view for the function under cursor.
    L     Open CloudWatch log streams for the function under cursor.
    F     Prompt to filter the list by function name.
    C     Clear the active filter.
    R     Re-fetch functions from AWS.
    D     Download the function source into lambda/<name>. Download only:
          no buffer is opened.
    E     Open the function source for editing. When no local copy exists
          the source is downloaded first and then opened.
    e     Edit the invoke payload (invoke.json, created as {} when missing).
    i     Invoke with invoke.json as the payload (see |aws-nvim-lambda-payload|).
    v     View response.json from the last invoke.
    I     Open the interactive invoke panel (see |aws-nvim-lambda-invoke|).
    U     Upload the local binding for the function under cursor.
    r     Upload the local binding, then invoke it with invoke.json.
    <S-L> Follow the function's CloudWatch logs (Shift-L toggles).
    q     Close the split window.

    All keys are configurable via |aws-nvim-keymaps|.

    The list is paginated and all pages are fetched automatically.

------------------------------------------------------------------------------
Invoke payload                                *aws-nvim-lambda-payload*

    A downloaded Lambda keeps three files next to its sources:

        lambda/<function-name>/
        |-- app.py
        |-- invoke.json        request payload, created as {}
        |-- response.json      result of the last invoke
        `-- .aws-resource.json metadata

    `invoke.json` is the only payload source. Pressing `i` runs:

        aws lambda invoke --function-name {name} \
          --payload fileb://invoke.json --cli-binary-format raw-in-base64-out \
          [--log-type Tail] response.json

    When invoke.json is missing, `i` creates it with {}, opens it and refuses
    to invoke ("invoke.json created. Please edit payload before invoking.").
    Invalid JSON is reported and never reaches the AWS CLI.

    `e` edits invoke.json (creating it when missing), `v` opens response.json,
    `r` uploads the source and then invokes with invoke.json. The payload path
    comes from get_current_payload_file(), so switchable payload sets can be
    added later without touching invoke logic.

------------------------------------------------------------------------------
Interactive invoke panel                      *aws-nvim-lambda-invoke*

    Opened with `I` in the functions buffer or :AwsLambdaInvoke from a bound
    source file. A horizontal split at the bottom of the editor contains:

    - a JSON payload box (filetype json) that starts from the last payload
      used for that function;
    - a button bar with [ Invoke ], [ Upload + Invoke ], [ Copy response ]
      and [ Close ]. Buttons react to <LeftMouse> as well as keys.

    Key   Action ~
    <C-s>   Invoke with the current payload.
    <C-CR>  Same as <C-s>.
    <C-a>   Upload the local binding, then invoke.
    q       Close the panel.
    <Esc>   Close the panel.

    Invalid JSON is reported inline and never reaches the AWS CLI. The result
    (StatusCode, RequestId, response body and decoded LogResult) opens in a
    floating buffer named aws://lambda/invoke-result/<name>.

    Open the IAM roles list buffer directly.

    Open the IAM policies list buffer directly.

    Open the detail view for a user.

:AwsIAM detail group {name} [--region {r}] [--profile {p}]
    Open the detail view for a group.

:AwsIAM detail role {name} [--region {r}] [--profile {p}]
    Open the detail view for a role.

:AwsIAM detail policy {arn} [--region {r}] [--profile {p}]
    Open the detail view for a managed policy.

:AwsIAM detail provider {arn} [oidc|saml] [--region {r}] [--profile {p}]
    Open the detail view for an identity provider. The kind defaults to
    `oidc` when omitted.

------------------------------------------------------------------------------
IAM detail buffers                               *aws-nvim-iam-detail-keys*
    filetype: `aws-iam`

    info in parallel. Policy detail fetches the policy document and
    attachment list in parallel.
